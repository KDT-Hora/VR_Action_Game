# Feature Specification: VR現実空間連動型・小世界アクションゲーム

**Feature Branch**: `001-vr-miniature-world`

**Created**: 2026-09-29

**Status**: Draft

**Input**: User description: "VR現実空間連動型・小世界アクションゲーム。VRヘッドセットで現実の部屋・机をスキャンし、ルールベース(AI不使用・決定論的)でステージを自動生成、プレイヤーは巨大な存在として小さなキャラクターを覗き込みながら操作してクリアを目指す。" (元資料: `VR現実空間連動型_小世界アクションゲーム_企画仕様書.txt`)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 小さなキャラクターを机の上で操作する (Priority: P1)

プレイヤーはVRヘッドセットを装着し、目の前の空間に配置された小さなキャラクター(現実に対して5〜20cm程度)を、巨大な存在として見下ろしながら直接操作して動かす。

**Why this priority**: 「小さな世界を覗き込む」という企画の核となる体験そのもの。サイズ感と操作感が成立しなければ以降の全機能に意味がない。単独でも検証可能なMVP。

**Independent Test**: 空間スキャンなしの固定ステージ上で、キャラクターの移動・ジャンプができ、顔を近づけて観察できることを確認する。

**Acceptance Scenarios**:

1. **Given** ゲーム開始直後、**When** プレイヤーが正面を見る、**Then** 現実空間に対して小さなキャラクターが視界内に表示される
2. **Given** キャラクターが表示されている、**When** プレイヤーが移動・ジャンプ入力を行う、**Then** キャラクターが入力どおりに動く
3. **Given** キャラクターが表示されている、**When** プレイヤーが顔を近づける・横から覗き込む、**Then** 視点が現実の身体の動きに追従し、キャラクターやステージを別角度から観察できる

---

### User Story 2 - 机などの平面上にステージを生成して遊ぶ (Priority: P2)

プレイヤーは机などの平面をスキャンし、その平面上に小さなゲームフィールド(Tabletop Mode)が生成され、キャラクターを操作して簡単なステージをクリアする。

**Why this priority**: 「現実空間からステージが生まれる」という第二の核。最初のプロトタイプで優先検証するモード。

**Independent Test**: 任意の机をスキャンし、その大きさに収まるステージが生成され、開始からゴールまで到達できることを確認する。

**Acceptance Scenarios**:

1. **Given** 机の前にいる、**When** 平面のスキャンを行う、**Then** 机の範囲が認識され、その範囲内にステージが生成される
2. **Given** ステージが生成された、**When** プレイヤーがキャラクターを操作してゴールに到達する、**Then** ステージクリアが表示される
3. **Given** 同じ空間データと同じ生成条件、**When** 再度ステージを生成する、**Then** 同一のステージが得られる

---

### User Story 3 - 部屋全体をスキャンしてステージを生成する (Priority: P3)

プレイヤーは部屋全体(床・壁・大型家具・段差)をスキャンし、家具などにゲーム上の別の意味(高台・壁・崖・柱など)を与えたステージ(Room Mode)が生成される。

**Why this priority**: 企画の完成形だが、机上モードより空間認識の難度が高いため後段。

**Independent Test**: 家具のある部屋をスキャンし、床・壁・大型家具が抽象化されたゲーム用空間データに変換され、それに基づくプレイ可能なステージが生成されることを確認する。

**Acceptance Scenarios**:

1. **Given** 家具のある部屋、**When** 部屋全体をスキャンする、**Then** 床・壁・大型家具・段差が簡略化された空間データとして取得される
2. **Given** 空間データがある、**When** ステージを生成する、**Then** 現実の家具がゲーム上の高台・障害物・壁などに対応づけられ、開始地点からゴールまで到達可能なステージになる

---

### User Story 4 - 敵・アイテム・ギミックを攻略してクリアする (Priority: P4)

生成されたステージ上に敵・アイテム・ギミック・宝箱・ボスなどが配置され、プレイヤーは攻撃・回避・ギミック操作を使って目的を達成し、次のステージへ進む。

**Why this priority**: 「ゲーム」として成立させる要素。ステージ生成の土台ができてから追加する。

**Independent Test**: 敵とギミックを含むステージで、攻撃・回避・ギミック操作を行い、クリア条件を満たして次ステージへ進めることを確認する。

**Acceptance Scenarios**:

1. **Given** 敵が配置されたステージ、**When** キャラクターが攻撃する、**Then** 敵が反応し、倒せる
2. **Given** ステージの目的(ゴール到達・宝取得・撃破・防衛・ボス撃破など)、**When** 条件を満たす、**Then** ステージクリアとなり次のステージへ進める

---

### User Story 5 - 同じ空間から異なる種類のステージを遊ぶ (Priority: P5)

同じ部屋・机から、探索型・宝探し型・戦闘型・防衛型・ボス型など異なる種類のステージを生成できる。

**Why this priority**: リプレイ性を高める拡張。基本ループが成立した後に追加する。

**Independent Test**: 同一の空間データから、ステージ種類を切り替えて生成し、それぞれ目的と配置が異なりクリア可能であることを確認する。

**Acceptance Scenarios**:

1. **Given** 同一の空間データ、**When** ステージ種類を変えて生成する、**Then** 目的・敵・ギミック配置が種類に応じて異なり、いずれもクリア可能である

---

### Edge Cases

- スキャンで十分な平面・空間が取得できない(狭い・暗い・反射面が多い)場合はどうするか
- 生成範囲内に到達不能なゴールやアイテムが生じないか(プレイ可能性の保証)
- スキャン中・プレイ中に現実の家具や人・ペットが動いた場合の扱い
- プレイヤーが現実の壁・家具・危険区域に近づいた場合の安全警告
- プレイヤーが極端に近づいた/遠ざかった場合のキャラクターの見え方
- 座位・立位など、プレイヤーの姿勢が途中で変わった場合
- スキャン結果が机の端や段差で不完全なとき、キャラクターが範囲外へ落ちる/出る場合
- ヘッドセットのトラッキングが一時的に失われた場合

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはVRヘッドセット上で、プレイヤーの現実空間に対して小さなキャラクター(5〜20cmの範囲で調整可能)を表示できなければならない
- **FR-002**: プレイヤーはキャラクターを直接操作(移動・ジャンプ・攻撃・回避・アクション・ギミック操作)できなければならない
- **FR-003**: プレイヤーの頭部の動きに応じて視点が追従し、覗き込み(近接・横・上下からの観察)ができなければならない
- **FR-004**: システムはゲーム開始時に現実空間をスキャンし、床・壁・天井・大型家具・平面・段差・空間の大きさを取得できなければならない
- **FR-005**: システムはスキャン結果を、ゲームに必要な情報のみを持つ簡略化された空間データへ変換しなければならない(小物の正確な認識は不要)
- **FR-006**: システムは Tabletop Mode(机などの平面上のステージ)と Room Mode(部屋全体を使うステージ)の2つのプレイ空間を提供しなければならない
- **FR-007**: システムは空間データから、開始地点・ゴール・敵・アイテム・障害物・ギミック・通路・高低差・宝箱・ボス・ステージ目的を自動生成しなければならない
- **FR-008**: ステージ生成はルールベース/アルゴリズムのみで行い、AIによる判断・生成を用いてはならない
- **FR-009**: ステージ生成は決定論的でなければならない(同じ空間データ・同じ生成条件からは同じステージが得られる)
- **FR-010**: 生成されたステージは、開始地点からゴール(または目的達成条件)まで到達可能であることを生成時に検証し、保証しなければならない
- **FR-011**: システムは現実の物体にゲーム上の別の意味(例:机→高台、棚→遺跡・壁、ソファ→山、段差→崖、机の脚→柱)を割り当てられなければならない
- **FR-012**: システムは同一空間から複数のステージ種類(探索型・宝探し型・戦闘型・防衛型・ボス型)を生成できなければならない
- **FR-013**: システムはステージクリア判定と次ステージへの進行を提供しなければならない
- **FR-014**: システムはプレイ可能範囲・プレイヤーの立ち位置・壁・家具・危険区域を管理し、危険が近い場合に警告しなければならない
- **FR-015**: プレイ中に現実の家具を破壊・移動する必要があってはならない
- **FR-016**: キャラクターにHPと戦闘不能の状態があり、難易度モードを2種類提供しなければならない。(a) チェックポイント復活モード: HPが0になるとチェックポイントから復活する。(b) 死亡なしモード: HPによる死亡がなく、落下などの場合のみ直前の安全な位置へ戻される
- **FR-017**: システムはPCVR接続のVRヘッドセット(パススルー/カメラ対応機)で動作しなければならない。対応する具体的機種・スキャン手段は計画フェーズで決定する
- **FR-018**: キャラクターの操作はVRコントローラー(スティック・ボタン)で行えなければならない

- **FR-019**: システムは空間データと進行状況を保存し、次回起動時に再スキャンなしで再開できなければならない
- **FR-020**: 現実空間はVR表示で隠されていても、プレイヤーは安全確認用にパススルーを一時的に確認できなければならない

### Key Entities

- **スキャン結果(Scan Result)**: 現実空間から取得した床・壁・天井・平面・家具・段差などの生の情報
- **空間データ(Spatial Data)**: スキャン結果をゲーム用に簡略化・抽象化したもの。領域、高低差、障害物、接続関係を持つ
- **プレイ空間(Play Space)**: Tabletop / Room のモードと、プレイ可能範囲・危険区域・プレイヤー立ち位置
- **ステージ(Stage)**: 生成された1つの遊べるフィールド。種類・目的・開始地点・ゴール・配置物を持つ
- **配置物(Stage Element)**: 敵・アイテム・ギミック・宝箱・ボス・障害物
- **キャラクター(Character)**: プレイヤーが操作する小さな存在。サイズ・HP・アクションを持つ
- **生成条件(Generation Seed/Conditions)**: 決定論的な再現に必要な入力(空間データ・ステージ種類・シード等)
- **進行(Progress)**: クリア済みステージや次ステージへの進行状態

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: プレイヤーは装着後3分以内に、スキャンからキャラクター操作開始まで到達できる
- **SC-002**: 生成されたステージの100%で、開始地点からクリア条件までの到達可能性が検証で確認される
- **SC-003**: 同一の空間データ・生成条件から生成したステージは、100回試行して100回とも同一である
- **SC-004**: 初見のプレイヤーの90%が、案内なしにキャラクターを移動・ジャンプさせ、覗き込みで観察できる
- **SC-005**: 対象環境(標準的な机・一般的な部屋)でスキャンからステージ生成完了までが1分以内に完了する
- **SC-006**: テストプレイの90%で、現実の壁・家具への接触や衝突警告の見落としが発生しない
- **SC-007**: 同じ空間から少なくとも3種類のステージ種類を生成でき、それぞれクリア可能である
- **SC-008**: プレイヤーの80%が「自分の空間が小さな世界になった」と感じたと回答する(体験評価)

## Assumptions

- 最初のプロトタイプは Tabletop Mode を優先し、Room Mode は後続段階とする(開発優先順位 Phase 1→6 に従う)
- プレイヤーはVRヘッドセットを装着し、十分に安全なプレイスペースを確保している
- ビジュアルは「現実を隠したVR表示」を基本とする(パススルーはスキャンや安全確認のために使用)。現実の物体はスキャンで取得した形状のみを材料にし、見た目はゲーム世界に置き換える
- スキャンした空間データと進行(クリア済みステージ)は保存され、再スキャンなしで再開できる(FR-019)
- 認識対象は床・壁・机・大型家具などの大まかな分類のみ。小物や家具の細かい種別判定は行わない
- 本仕様ではハードウェア・ゲームエンジン・スキャン技術などの実装選定は行わず、計画フェーズで決定する
- ゲーム内でAIは使用しない。ステージ生成はルールベース・決定論的とする
- 世界観・キャラクターデザイン、アイテム・ギミックの具体的種類は後続の仕様化で決定する
- 現実空間は忠実に再現せず、ゲームステージの「材料」として抽象化して使う
- キャラクターのサイズは設定で5〜20cmの範囲を調整可能とし、既定値は計画段階で決める
- 単独プレイ(1人)を前提とする
